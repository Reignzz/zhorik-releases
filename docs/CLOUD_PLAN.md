# Жорик в облаке: план работ

Цель: бот @odesbud_bot со своей логикой и ответами продолжает работать, когда на компьютере кончились лимиты
Claude Code или компьютер выключен. Исходники и логика — на нашем GitHub.

## Что известно сейчас

Из установщика Жорика 0.5.0 (`app.asar`) и проверки окружения 25.09.2026:

- **Жорик на рабочем столе** (Electron, `src/main.js`, `src/botlink.js`) — только «лицо»: реплики из `content/*.md`,
  расписание, напоминания. Сам он не думает: слушает посредника `https://zhorik-relay.mrreignz.workers.dev`
  (Cloudflare Worker; `/v1/pair/*`, `/v1/events`) и показывает события `user_message`, `bot_reply`, `brief`,
  `task_done`, `reminder`, `hint`.
- **«Мозг» — Telegram-бот @odesbud_bot**: отвечает Маргарите, присылает бриф к 07:00, задания, напоминания.
  Он работает на компьютере владельца — по всем признакам это сессия Claude Code с каналом Telegram
  (`claude --channels plugin:telegram@claude-plugins-official`): плагин опрашивает Telegram через `getUpdates`,
  сообщения приходят в сессию как `<channel source="…telegram…" chat_id=… message_id=…>`, ответ уходит инструментом `reply`.
  Точно подтвердит инвентаризация (этап 1).
- **Исходников бота и посредника на GitHub нет**: `zhorik-releases` — только установщики, `WingField` — другой проект.
- **Главное ограничение: облачные сессии Claude Code делят лимиты с компьютером** («cloud sessions share rate limits
  with all other Claude and Claude Code usage within your account» — документация Claude Code). Проверено на деле:
  сессия, запущенная на компьютере, сразу упала с «You've hit your session limit · resets 10:20am (UTC)».
  Значит, «перенести бота в облачную сессию Claude Code» от лимитов **не спасает**. Резерву нужен свой бюджет:
  **ключ API Anthropic** (оплата по факту).

## Решение

Основной мозг остаётся на компьютере (там его файлы, логины, бриф). Облачный резерв на GitHub Actions
включается сам и отвечает от имени того же бота, с тем же CLAUDE.md:

```
Маргарита ──► Telegram ──► плагин на компьютере ──► Claude Code (подписка)
                                      │                   │ лимит/сбой → хук StopFailure
                                      │                   ▼
                                      │        repository_dispatch ──► GitHub Actions
                                      │                                  claude -p (ключ API) + CLAUDE.md бота
компьютер выключен:                   ▼                                  │
пульса нет ──► Actions по расписанию сам берёт getUpdates ───────────────┴──► sendMessage в тот же чат
```

Готово в этой ветке (`cloud/`, 17 тестов проходят): `answer.mjs`, `lib.mjs`, `workflow.yml`, `hooks/handoff.mjs`,
`hooks/heartbeat.mjs`, промпт резервного режима, черновик характера. Подробности и установка — `cloud/README.md`.

Отдельно, без кода: если в настройках аккаунта claude.ai доступно **Extra usage** (докупка сверх лимита по ценам API),
его включение уже решает «кончились лимиты» — бот на компьютере просто продолжит работать. Выключенный компьютер
это не покрывает; облачный резерв покрывает оба случая.

## Этапы

### 1. Инвентаризация на компьютере — ждёт сброса лимита
Сессия на компьютере (`projects-main`, Remote Control) по промпту `docs/prompts/01-local-inventory.md`: найти исходники
Жорика, посредника и мозга бота, выгрузить их **без секретов** в приватный `Reignzz/zhorik`, написать
`docs/CLOUD_HANDOFF.md` (как всё запущено, где характер и логика, секреты — только имена).
Первый запуск 25.09 в 09:50 UTC упал по лимиту; повтор запущен в 10:22 UTC.
**Готово, когда:** приватный репозиторий есть, в нём исходники и docs/CLOUD_HANDOFF.md, секретов нет.

### 2. Доступ облака к приватному репозиторию — владелец
Установить Claude GitHub App на `Reignzz/zhorik` (https://github.com/apps/claude/installations/select_target),
чтобы облачные сессии могли в нём работать.

### 3. Перенос резерва в приватный репозиторий — облачная сессия
По промпту `docs/prompts/02-cloud-integration.md`: `cloud/` → в приватный репозиторий, workflow → `.github/workflows/`,
`ZHORIK_BOT_DIR` → папка с настоящим CLAUDE.md (черновик `persona.md` больше не нужен), сверить формат `<channel>`
и имя инструмента `reply` с реальным транскриптом, подключить события посредника (`bot_reply`), если у бота
есть для этого API.

### 4. Секреты и настройка — владелец (10–15 минут)
- Секреты Actions: `TELEGRAM_BOT_TOKEN`, `ANTHROPIC_API_KEY` (отдельный ключ с лимитом расходов в console.anthropic.com),
  `ZHORIK_ALLOWED_CHATS`.
- Fine-grained токен GitHub только на `Reignzz/zhorik` (Contents RW, Variables RW) → `~/.claude/zhorik-cloud.env` на компьютере.
- Хук `StopFailure` (`cloud/hooks/settings.example.json`) и пульс раз в 5 минут (`cloud/hooks/heartbeat.mjs`).
- Правило в CLAUDE.md бота, чтобы после сброса лимита он не ответил второй раз:
  > Если в `~/.claude/zhorik-handoff.json` (поле `sent`) есть ключ `<chat_id>:<message_id>` сообщения — на него уже
  > ответил облачный резерв. Не отвечай на него повторно; учитывай, что разговор мог продолжиться в облаке.

### 5. Проверка
- Actions → Run workflow с `dry_run` — ответ в журнале; затем без `dry_run` — ответ в Telegram.
- Искусственный сбой хука (matcher `unknown`) — сообщение уходит в облако, ответ приходит один раз.
- Остановить бота на компьютере на 25 минут в рабочее время — облако отвечает само; запустить обратно — облако отступает.

### 6. Потом (по желанию)
- Бриф в 07:00 из облака, если компьютер его не прислал (нужно знать, откуда бриф берёт данные — из этапа 1).
- Журнал облачных разговоров, который компьютер подхватывает после возвращения (контекст для основной сессии).
- События посредника из облака, чтобы десктопный Жорик показывал «думаю» / «ответил в Telegram» и в резерве.

## Кто что делает

| Шаг | Кто |
|---|---|
| 1. Инвентаризация и выгрузка исходников | сессия на компьютере (автоматически, после сброса лимита) |
| 2. Claude GitHub App на приватный репозиторий | владелец, 1 минута |
| 3. Перенос резерва | облачная сессия |
| 4. Секреты, токен, хук, пульс | владелец (секреты вводятся только руками) |
| 5. Проверка | вместе |

## Риски

- **Двойной ответ** после сброса лимита — правило в CLAUDE.md (этап 4) и дедупликация в хуке.
- **Два опросчика Telegram одновременно** — облако берёт `getUpdates`, только когда пульса нет дольше 20 минут;
  без настроенного пульса не берёт никогда.
- **Утечка переписки** — только приватный репозиторий (проверяется в коде), тексты сообщений в журналы не пишутся,
  токены Telegram/GitHub в окружение `claude` не передаются, отвечаем только чатам из `ZHORIK_ALLOWED_CHATS`.
- **В резерве нет инструментов компьютера** (почта, диск, отметка задач) — резерв честно говорит, что сделает позже.
- **Деньги** — ключ API с лимитом расходов; модель меняется переменной `ZHORIK_MODEL`.
