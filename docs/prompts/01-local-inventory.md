# Промпт 1 — инвентаризация на компьютере

Для сессии Claude Code на компьютере владельца (Remote Control, окружение `projects-main`). Запускается из облачной
сессии через `create_session` или вручную: `claude` в папке с проектами, вставить текст ниже.

---

Задача: найти на ЭТОМ компьютере все исходники «Бот Жорик · Профосвіта» и «мозг» Telegram-бота @odesbud_bot, выгрузить их в ПРИВАТНЫЙ репозиторий GitHub и описать, как всё работает, чтобы облачная сессия Claude Code могла продолжить работу бота, когда здесь кончаются лимиты. Владелец попросил это сам («найди исходные файлы у меня локально и работай с ними через облако»). План целиком: https://github.com/Reignzz/zhorik-releases/blob/claude/zen-clarke-ea8j8h/docs/CLOUD_PLAN.md

Что уже известно (из собранного установщика v0.5.0 в github.com/Reignzz/zhorik-releases):
- Десктоп-приложение Electron: package.json "name": "zhorik", файлы src/main.js, src/botlink.js, src/lines.js, content/*.md; в исходниках должны быть docs/bot-link.md, tools/release.sh, tests/scenario.js.
- Посредник (relay): https://zhorik-relay.mrreignz.workers.dev (Cloudflare Worker), API /v1/pair/start, /v1/pair/status, /v1/events; события user_message, bot_reply, brief (утренний бриф ~07:00), task_done, reminder, hint.
- Telegram-бот: @odesbud_bot. Именно он отвечает Маргарите, присылает бриф и задания. Скорее всего его «мозг» — сессия Claude Code (канал/плагин Telegram, CLAUDE.md, скиллы, расписание), но это надо проверить.

Шаги:
1. Найди всё, что относится к Жорику и боту. Ищи в ~/projects, ~, ~/Documents, ~/Desktop, ~/code, ~/dev и т.п. Маркеры: package.json с "name": "zhorik"; docs/bot-link.md; wrangler.toml/wrangler.jsonc с zhorik-relay; любые файлы с "odesbud_bot", "zhorik-relay", "Профосвіта", "Маргарит"; настройки Claude Code, которые задают поведение бота (CLAUDE.md, .claude/skills, .claude/agents, .claude/settings.json, .mcp.json, ~/.claude/channels/telegram/ — из последнего бери ТОЛЬКО структуру, без токенов). Как бот запускается: crontab -l, launchctl list | grep -i -E "zhorik|claude|telegram", systemctl --user list-units, pm2 ls, tmux ls, screen -ls, ps aux | grep -i -E "claude|telegram|zhorik|wrangler".
2. НИЧЕГО не останавливай, не перезапускай и не меняй в работающем боте, посреднике и Жорике. Разрешены только чтение и git-операции для выгрузки.
3. Секреты не выгружать ни в коем случае: .env*, токены Telegram (вид 123456789:AA…), sk-ant-…, токены Cloudflare/GitHub, relayToken, access.json с id чатов, ключи подписи. Добавь .gitignore, перед push прогони поиск по шаблонам токенов по всему, что коммитишь. В документации указывай только ИМЕНА секретов и где они лежат, без значений. node_modules, dist, release, *.dmg, *.exe не коммить.
4. Выгрузка:
   - если проект уже git-репозиторий с remote на GitHub — запушь туда текущие ветки (без force-push) и запомни имя репозитория;
   - иначе создай приватный репозиторий Reignzz/zhorik (gh repo create Reignzz/zhorik --private …) и выложи туда всё: приложение, посредник (worker), мозг бота (промпты/CLAUDE.md/скиллы/скрипты/расписание) — отдельными папками, например app/, relay/, bot/. Существующую git-историю сохрани, ничего не переписывай;
   - репозиторий должен быть ПРИВАТНЫМ (zhorik-releases публичный — туда исходники НЕ класть);
   - если gh не установлен или не авторизован — не выдумывай обходы с чужими токенами: подготовь локальный коммит и напиши в итоге, какую одну команду владельцу выполнить.
5. Напиши в репозитории docs/CLOUD_HANDOFF.md (по-русски):
   - схема: кто принимает сообщения Telegram (getUpdates или webhook, какой процесс), где «мозг», как события попадают в посредника и в Жорика;
   - точные пути на этом компьютере и команды запуска каждой части, чем запускается (launchd/cron/tmux/pm2/вручную);
   - где заданы характер, логика и реплики бота (файлы), расписание (бриф 07:00, напоминания), что бот помнит между разговорами и где это хранится;
   - все секреты и переменные окружения — только имена и откуда берутся;
   - зависимости: версии node/wrangler/claude, плагины и MCP-серверы, логины, которые есть только на этом компьютере;
   - как выглядят в транскрипте Claude Code входящее сообщение Telegram и вызов инструмента ответа (формат тега <channel …> и имя инструмента reply) — на одном примере, текст сообщения замени на «…»;
   - что сейчас происходит, когда у Claude Code кончаются лимиты (бот молчит? ошибка в Telegram? есть ли логи — приложи пару строк без личных данных);
   - что нужно, чтобы тот же мозг мог работать в облаке.
6. В конце выведи короткий итог: URL репозитория, ветку, хеш коммита, что не удалось и почему.
